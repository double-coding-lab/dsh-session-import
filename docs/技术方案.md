# dsh-session-import 技术方案

## 需求概述

- **背景**：日常开发会在多个 AI 编程工具之间切换（Qoder、Claude Code、Codex、WorkBuddy 等），每个工具把会话写进各自的私有目录，格式互不相通。切到 DeepSeek Harness（DSH）之后，过去积累的上下文无法继承，只能重新解释一遍需求与决策。
- **目标**：做一个 DSH 插件，把第三方 agent 的会话**导入成 DSH 原生会话**——能浏览、能搜索、**能直接续聊**，并且在侧栏出现在正确的项目下。
- **核心设计目标**：新增一个工具的支持**只需加一段 `provider.json`**，不改核心代码。同族格式（Claude 系 jsonl）零代码接入，只有全新格式家族才写解析器。
- **范围（v1）**：Qoder、Claude Code、Codex 三个 provider；**只做会话**——导入为可续聊的 DSH 会话；面板勾选导入；幂等与增量同步；导入报告与撤回。
- **明确不做**：
  - 不做反向导出（v1 只读源、只写 DSH）。
  - 不做记忆（memory）。DSH 没有记忆这个一等概念，写进任何目录都没有消费方，唯一能生效的容器是 `AGENTS.md`——而那是**指令**，语义不同，等于用错容器。接入了也是死胡同。
  - 不迁移技能（skills）、MCP 连接器、settings、hooks。技能与 MCP 在 DSH 生态已有专门插件（`dsh-skill-importer`、`dsh-mcp-hub`、本组织自己的 `dsh-connectors`），重复实现没有价值。
  - 不解析 IDE 内嵌聊天（如 `state.vscdb` 里的对话），v1 只处理落盘的会话文件。
  - 不做云同步、不做多机共享。

## 重点问题概述

以下 7 条是设计约束，均来自对现有实现（Codex 官方迁移、`casr`、`continues`、`session-migrate`、`qoder-continues` 以及 DSH 生态内 8 个同类插件）的比对结论，不是自由选择。

| # | 问题 | 决策 |
|---|---|---|
| 1 | **可续聊 vs 上下文预算**。DSH 续聊时由 `deriveMessages()` 把 surface 事件全量还原成消息序列；一个 65 MB 的第三方会话直接导入必然不可用 | 默认只导入**可续聊窗口**（保留最近 N 轮完整对话 + 更早轮次的摘要头），全量导入需显式选择 |
| 2 | **单个超大事件无法被压缩**。DSH 的 compaction 只能替换 surface 节点，压不掉单条巨型 `tool_result` | 导入期对每个文本块做**硬上限截断**（默认 262,144 字符），保留头尾并插入显式标记 |
| 3 | **推理块不可跨端重放**。Claude 系与 Codex 的 thinking 带签名或服务端加密，换宿主后无效 | **默认丢弃**；全量档仅保留明文 summary |
| 4 | **工具轮次必须闭合**。DSH 的 projection 遇到「`tool/result` 前没有未闭合的 `tool/call`」会判定 surface 损坏，整段历史读不出来 | **双向修复**：无主的 result 补占位文本、无结果的 call 补确定性错误结果 |
| 5 | **幂等**。会话文件会持续增长，重复导入不能产生副本 | 状态文件记录「源指纹 → DSH 会话 ID + 已导入偏移」，增量只 append 新段 |
| 6 | **安全边界**。插件要读其他工具的私有目录 | 源目录**只读**；路径必须规范化后仍在白名单根内，禁止符号链接逃逸；不跟随、不写入源目录 |
| 7 | **别把「别的工具的资产」都当成本插件的事**。Qoder/Codex 的导入页把会话、记忆、技能、MCP 并列，看着都该做 | 只做**有 DSH 消费方**的资产。会话有 `ctx.sessionPersistence` 接手；记忆没有，技能和 MCP 已有专门插件——接入没有落点的数据是负资产 |

## 外部依赖与内部调用

**依赖的 DSH 服务**

| 服务 | 用途 |
|---|---|
| `ctx.sessionPersistence` | `create(header)` 建会话、`append(id, events)` 写事件、`inspect(id)` 回读自检 |
| `ctx.storage`（`dsh-storage-domain`） | 存导入映射表、扫描缓存、用户偏好 |
| attachment store | 图片等附件落地，使导入后的历史仍能渲染并回喂模型 |
| Web client slot | 侧栏面板与进度展示 |

**已核验的第三方会话位置**

| Provider | 路径 | 格式家族 |
|---|---|---|
| Qoder | `~/.qoder/projects/<项目编码>/<uuid>.jsonl` | `claude-jsonl` |
| Claude Code | `~/.claude/projects/<项目编码>/*.jsonl` | `claude-jsonl` |
| Codex | `~/.codex/state_5.sqlite`（threads/projects）+ `~/.codex/thread_history_1.sqlite`（thread_turns/thread_items）+ `~/.codex/.codex-global-state.json`（桌面项目与线程归属） | `codex-db` |
| WorkBuddy（M4） | 待定位（安装目录在 `D:\WorkBuddy`，数据目录待确认） | 待定 |

**不引入**任何第三方 SDK；解析、映射、写盘全部用 Node 内置能力。

## 配置

插件在 profile 中的配置项：

```yaml
- id: dsh-session-import
  name: "@double-coding/dsh-session-import"
  config:
    showSidebarEntry: true      # 是否在侧栏显示「会话导入」入口
    fidelity: window            # window | full —— 默认只导可续聊窗口
    maxTurns: 80                # window 档保留的最近轮数；0 表示不限
    perTextLimit: 262144        # 单条文本硬上限（字符），超出保头尾截断
    keepReasoning: false        # 是否保留明文推理摘要
    providers: {}               # 按 provider id 覆盖 roots，例如 { qoder: { roots: ["D:/qoder-data"] } }
```

运行时不可配置的硬约束：源目录只读、路径越界即拒绝、导入前必须 `inspect` 自检。

## 交付单元

### Provider 描述文件（`providers/<id>/provider.json`）

**业务说明**：一个内置 provider 就是一份纯数据描述，不含可执行代码，因此社区贡献新工具只需提交 JSON + 一份脱敏样例。

**输入/输出**：读取时与 `schema/provider.schema.json` 校验；输出一个 `ProviderDescriptor`。

**fileLinks（按 provider 数据）**：Qoder 为 `markdown-link` + `file-url`；Claude Code 为 `markdown-link` + `absolute-path`（assistant 写 `[周报.txt](C:\Users\…\Desktop\周报.txt)`，导入后转成 basename inline code + `deliverables/presented`，即原生可点击文件 chip）。Claude Code 的用户图片是消息内 base64 block，经 `data:` URL 走同一附件转存路径。

**标题同源**：列表提示与导入解析使用同一优先级——`aiTitle` / `customTitle` 优先，首条用户消息兜底。Claude Code 的 `ai-title` 记录写在首轮之后（长转录里可能在文件尾部），提示需读取头部 256KB + 末尾 64KB，不能遇到首条消息就提前定标题；提示缓存带版本号，提取规则变化时整体失效。

**`sessions.ignore`**：机器遥测、内部探针类转录不是真人对话，在扫描阶段按提示元数据排除，不出现在导入面板；已导入过的记录仍保留，撤回入口不丢。规则属于 provider 数据，支持两种匹配：`titlePrefixes` 按解析标题前缀（如 Qoder 安全插件 CodeSec 上报的 `codesec_telemetry` / `codesec_review`）；`sessions` 按会话元数据逐条匹配，一条规则内的条件需同时满足，可选 `cwdContains`（cwd 子串，忽略大小写）与 `title`（标题全等）。Claude Code 桌面端启动时会在 `claude-sandbox-status-<id>` 临时目录跑一条 `sandbox` 探针，用 `{ "cwdContains": "claude-sandbox-status-" }` 隐藏。

**Codex 桌面数据库**：Codex Desktop 的会话主存是 `state_5.sqlite`（`threads` 全量线程 + `projects`/`project_roots`）与 `thread_history_1.sqlite`（`thread_turns` + `thread_items`），`~/.codex/sessions` 下的 rollout 已改为 `.jsonl.zst`，且每条线程会拆成多段，不能再作为完整来源。provider 使用 `family: "codex-db"` 与 `layout.database` 声明三个路径；扫描先按 `thread_source` 为 null/user、`source` 不是 JSON 子代理标记、`archived = 0`、至少一条 `userMessage` 过滤，再用 `thread_turns.status <> 'inProgress'` 的 item 数作为指纹与「有新增」判定。工作区分组优先取 `.codex-global-state.json` 的 `thread-project-assignments` / `local-projects`，缺失时按 cwd 匹配项目根目录；未归属项目的线程合并到「聊天」，不伪造工作区（Codex 侧栏的「最近」是跨项目快捷入口，同一会话仍归属项目，导入面板不重复列出）。扫描同时隐藏内部子代理线程（`thread_source` 非 user，或 `source` 为 JSON 子代理标记）和机器批量提示（codex-ppt 的 `Generate slide …`、Open Design、git-commit-helper 等，规则在 provider 的 `ignore.titlePrefixes`）。导入按 `rollout_ordinal` 读取已完成回合：`userMessage` 剥离 `# Context from my IDE setup` / `# Files mentioned by the user` 包装与 `## My request for Codex:` / `## My request:` 标记，`localImage` 转为图片附件；`agentMessage`、`reasoning`、`commandExecution`、`fileChange`、`mcpToolCall`、`webSearch`、`dynamicToolCall`、`plan` 映射为事件，工具调用与结果成对写入。数据库没有可 stat 的文件，解析器自带 `fingerprint`（已完成 item 数 + `updated_at_ms` + 线程哈希）；旧账本仍指向 rollout 时，扫描标记 `sourceChanged`，导入按数据库内容原地重建同一 DSH 会话。自检 `scripts/test-codex-db.ts`（项目归组、包装剥离、仅已完成回合、图片、增量、旧账本重建）。旧的 `codex-jsonl` 解析器保留给未压缩 rollout 与回归测试，内置 Codex provider 已不再使用。

```json
{
  "$schema": "../../schema/provider.schema.json",
  "schemaVersion": 1,
  "id": "qoder",
  "name": "Qoder",
  "family": "claude-jsonl",
  "assets": {
    "sessions": {
      "roots": { "win32": ["~/.qoder/projects"] },
      "layout": { "sessionGlob": "*/*.jsonl", "subagentGlob": "*/subagents/*.jsonl" },
      "cwd": { "from": "workspace-directories.directories[0]" },
      "title": { "fields": ["aiTitle", "customTitle"], "fromFirstUserMessage": true },
      "ignore": { "titlePrefixes": ["{\"codesec_telemetry\"", "{\"codesec_review\""] }
    }
  },
  "fileLinks": {
    "assistant": [
      { "syntax": "markdown-link", "accept": ["file-url"] }
    ]
  },
  "capabilities": { "resume": true, "images": true, "subagents": true }
}
```

**字段说明**

| 字段 | 类型 | 说明 |
|---|---|---|
| `family` | string | 会话解析器家族：`claude-jsonl` \| `codex-jsonl` \| `codex-db` |
| `assets.sessions.roots` | object | 按平台给出会话根目录，支持 `~` 展开 |
| `assets.sessions.layout.sessionGlob` | string | 相对 root 的会话文件匹配式（数据库 family 仅作占位） |
| `assets.sessions.layout.database` | object | SQLite family 的 `state` / `history` / `globalState` 文件名，相对 provider 根目录；扫描自动跟随版本号升高的 `state_N` / `thread_history_N` |
| `assets.sessions.cwd.from` | string | 从哪条记录/字段取工作目录，取不到则归入「未归类」 |
| `fileLinks.assistant` | array | 该 provider 写本地文件的链接规则；不写则保持源文本 |
| `capabilities` | object | 声明支持能力，面板据此置灰不支持的选项 |

**处理流程**：启动时枚举 `providers/*/provider.json` → schema 校验（失败则该 provider 标为不可用并在面板提示，不影响其他 provider）→ 按当前平台展开 roots → 交给扫描服务。

### 家族解析器（`src/host/parsers/<family>.ts`）

**业务说明**：把某个格式家族的原始记录流归一成中间表示。解析器只认格式，不认具体工具。

**输入/输出**：输入为文件路径（流式逐行读取，不整文件载入内存）；输出为 `SourceEvent[]`。

**处理流程**：
1. 逐行 JSON 解析，坏行跳过并计数（不中断整份导入）。
2. 按 `parentUuid` / `active-leaf` 重建**主线**：从最终 active leaf 反向回溯，得到线性序列；`isSidechain: true` 的记录分流到子会话。源工具只有正常退出才写 `active-leaf`，缺失或指向已失效记录时，回退到**最新的一条无子节点消息**作为叶子，多条候选时优先非 sidechain，避免崩溃/中断的会话被误判为空。
3. 按记录类型归一到 `SourceEvent`，未识别类型计入 `ignoredTypes` 统计。

### 中间表示 `SourceEvent`（`src/shared/types.ts`）

**业务说明**：解析器与映射器之间唯一的契约，也是「加工具不改核心」的关键层。

```ts
type SourceEvent =
  | { kind: 'user';       time: number; text: string; attachments?: SourceAttachment[] }
  | { kind: 'assistant';  time: number; text: string; model?: string; files?: SourceFileReference[] }
  | { kind: 'reasoning';  time: number; text: string }
  | { kind: 'tool-call';  time: number; callId: string; name: string; args: string }
  | { kind: 'tool-result';time: number; callId: string; text: string; isError?: boolean }
  | { kind: 'turn-boundary'; time: number }
```

### 文件链接适配（`src/host/file-links.ts`）

**业务说明**：不同工具写本地文件链接的方式不同。Qoder 用 `[名](file:///D:/…)`，其他工具可能写绝对路径或工作区相对路径。适配器本身不认工具，只执行 provider 的 `fileLinks` 规则。

**输入/输出**：`SourceEvent[]` + provider 规则 + 会话 cwd；输出仍是 `SourceEvent[]`，但 assistant 文本里的链接已改为 inline code，事件上附带 `files: [{ path, description? }]`。

**规则字段**

| 字段 | 取值 | 说明 |
|---|---|---|
| `syntax` | `markdown-link` | 当前支持的源语法 |
| `accept` | `file-url` \| `absolute-path` \| `relative-path` | 哪些链接目标算本地文件；相对路径按会话 cwd 解析 |
| `extensions` | `[".md", ".pdf"]` | 可选扩展名白名单 |

**为什么改成 inline code**：DSH 的 assistant markdown 只放行 http/https 链接，`file://` 会退化为纯文本。DSH 原生支持的是「inline code 命中本轮交付文件 → 渲染成可点击文件 chip」，因此适配器把链接改成文件名（同名冲突时用完整路径），并由映射器写入同轮 `deliverables/presented`。

**边界**：DSH 只为每轮收尾的 assistant 消息提供文件提及解析，轮中过程消息的链接保持普通文本；适配只依赖源文本与规则，不检查文件是否存在，保证增量导入的前缀哈希稳定。

**新增 provider 写法**：在 `providers/<id>/provider.json` 增加 `fileLinks.assistant` 即可，无需改适配器。Qoder 声明 `file-url`；若某工具输出 `[名](/abs/path.md)`，声明 `absolute-path`（Claude Code、Codex 都是这一种）；输出工作区相对路径则声明 `relative-path`。

### 映射器（`src/host/mapper.ts`）

**业务说明**：把 `SourceEvent[]` 转成 DSH 的 `SessionEvent[]`，是唯一依赖 DSH 事件语义的环节。

**事件映射**

| SourceEvent | DSH 事件 |
|---|---|
| `turn-boundary` | `turn/start` / `turn/end` |
| `user` | `user/message`（`surfaceOp: 'append'`） |
| `assistant` | `step/start` + `assistant/message` + `step/end` |
| `assistant.files` | 先写 `deliverables/presented`（同轮按路径去重） |
| `tool-call` | `tool/call` |
| `tool-result` | `tool/result` |
| `reasoning` | 丢弃；`keepReasoning: true` 时写 `assistant/chunk` |

**处理流程**：
1. 丢弃源端噪音：`system`、`runtime-config`、`file-history-snapshot`、`last-prompt`、`active-leaf`、源工具的上下文注入信封（如 `AGENTS.md` 指令块、`<environment_context>`）、`isMeta: true` 的系统注入消息（如 `[Image: original 4096x3072…]` 标注）。
2. 应用截断策略（`perTextLimit`、`keepReasoning`）。
3. **配对修复**：先扫一遍 call/result 集合，result 无主 → 丢弃并计数；call 无果 → 补一条确定性错误结果。
4. 生成单调递增 `seq` 与 `time`，产出连续事件数组。

### 导入管线（`src/host/importer.ts`）

**业务说明**：真正落盘的地方，也是所有校验的入口。

**输入**：`{ providerId, sourcePath, sessionId, options }`；**输出**：`ImportResult`。

**处理流程**：
1. 计算源指纹（文件大小 + 修改时间 + 首行哈希）。
2. 查映射表：已导入且指纹未变 → 直接返回 `skipped`；已导入且源有增长 → 走增量分支。会话若已在 DSH 中打开（持有日志写句柄）：正在回复的拒绝（提示等本轮结束）；空闲或 attached 的先 evict（复用撤回的生命周期卸载：取消 Agent、注销会话）再追加，无需重启 DSH；evict 失败才返回「请重启 DSH 或撤回后重新导入」。增量追加前做三重校验：首部 64 事件哈希（窗口未滑动）、追加游标前 32 事件的边界哈希（解析规则未漂移）、尾段必须以 `turn/start` 开始；回合号按 DSH 日志当前最大回合继续重编号（会话在 DSH 里被继续过也不会撞号）。边界不符、存在未闭合回合或编号无法衔接时拒绝追加并提示撤回重导，绝不写入可能损坏的日志。若既有 DSH 日志本身已不可读（历史版本遗留的损坏），增量导入直接返回「请先撤回再重新导入」的明确提示，而不是抛出原始 SessionFormatError。
   **rewind 分叉**：Claude Code 的 Rewind/Undo rewind 会把后续对话写进**新的转录文件**，并复制分叉点之前的消息（UUID、时间戳不变）；旧文件保留被放弃的分支。扫描以「首条用户消息 UUID」作为血缘 ID 归并同一会话的所有分支，只展示最后一条消息最新的活跃分支，行仍绑定首次导入那条记录的 `sourceSessionId`；活跃分支路径与记录 `sourcePath` 不同即标记“有新增/可重新导入”。导入时若记录已存在、路径变化且血缘一致（记录无 `lineageId` 时读取旧文件首条用户 UUID 校验），走**重建**：evict 会话 → 删除旧 DSH 日志与记录 → 用同一逻辑 ID（因而同一 `dshSessionId`）重新写入活跃分支；被 rewind 的旧回合不会保留，账本 `sourcePath` 跟随活跃分支。血缘不一致的替换一律拒绝重建，交给增量校验兜底。源工具文件始终只读。
3. 解析 + 映射，得到事件批次。
4. `sessionPersistence.create(header)`，`header.cwd` 取源会话记录的 cwd，使会话归位到对应项目。
5. 分批 `append`，每批后回报进度。
6. `inspect(id)` 回读，校验事件链完整、seq 连续；失败则标记 `failed` 并在报告中给出首个异常事件。
7. 写映射表，返回 `ImportResult{ status, sessionId, turns, events, truncated, repaired, ignored }`。
8. 图片：映射前解析用户消息的 `image` 块——优先读源工具本地副本（Qoder 在 `~/.qoder/tmp/<project>/images/<session>/`，路径取自「附件引用」列表并按顺序配对），否则用签名 URL / `data:` 兜底；嗅探 PNG/JPEG/WebP/GIF 后经 `ctx.attachments.saveImages` 转存为 DSH 附件引用，事件写成原生 `{type:"image", attachment}` 块（位于文字前）。无法解析的图片直接丢弃，导入不因图片失败。图片全部转存成功时，用户文本里对应的「附件引用：- 文件：…」图片行会被移除（该节只剩图片行时连标题一起去掉）；有图片未能转存则保留原文。
9. 标题回填：仅当事件链中存在真人 `user/message` 时写 `session/title`。DSH 要求非 user 标题的 `messageSeqs` 必须引用更早的真人消息，空 `messageSeqs` 仅限 user 标题；纯工具会话（无真人消息）不写标题，否则整条日志会被判损坏（未命名 + 历史加载失败）。

### 扫描与 HTTP 路由（`src/host/discovery.ts` + `src/host/routes.ts`）

**业务说明**：面板的数据源。扫描只产出元数据，**导入时重新读盘**，不信任扫描快照。

| 路由 | 方法 | 说明 |

| `/dsh-session-import/api/import/:id` | GET | 查询进度与逐条结果 |
| `/dsh-session-import/api/retract` | POST | 撤回某次导入（删除本插件创建的会话及其映射）；若该工作区已无其他会话，同时注销空工作区注册（保留磁盘目录与日志） |

**会话元数据字段**

### 面板（`src/client/`）

**业务说明**：侧栏「会话导入」页。

**交互**：应用 → 工作区 → 会话三级结构，照 DSH 设置页的数据层级组织，不做卡片套卡片：

```
🔍 搜索工作区或会话
☑（三态） Qoder                          133 个会话 · 27 个工作区 ⌄
  ☐ folder 成渝研究院-数据要素平台升级   3 个会话 ◐（tooltip：部分已导入 2/3） ⌄
  ☑ folder internet-safe               5 个会话 ✓（tooltip：已全部导入） ⌄
      ☐ 会话标题                                     ✓（悬停 ↺）
```

- 顶部搜索：按工作区名/路径或会话标题过滤，命中自动展开；无结果显示「没有匹配的会话」；清空恢复原有折叠状态。
- 首次加载：健康检查与所有 provider 扫描并行执行，骨架行（行首方块 + 图标块 + 名称条 + 行尾计数条，分组间有分隔线）覆盖整个过程，完成后一次性渲染真实行；不再出现「先出应用行、再补扫描」的两段式加载。骨架使用 DSH 模块底色 + 脉动动画，`prefers-reduced-motion` 下静态降级。扫描按文件 16 路并发、只读转录前 256KB，并用 `~/.dsh/session-import/scan-cache.json` 按 `(bytes, mtimeMs)` 缓存每条转录的标题/cwd/首行哈希：命中只 stat 不读文件头，变更文件重读，枚举完整时才清理失效条目（原子写 + 串行队列）。扫描支持 provider 的 `sessionGlobs` 多层级枚举，并按 `lineage.mode` 决定“只显示最新 rewind 分支”还是“合并所有 rollout 段”。`codex-db` 不遍历文件，而是只读打开 SQLite，用一次分组聚合得到每条线程的已完成 item 数与用户消息数，项目归属来自全局状态 JSON；实测 700 条线程、12 万级 items 的扫描仍在百毫秒级。实测服务启动完成后的首扫约 0.1s、随后约 0.07s（旧实现 3.7s），无缓存首次构建约 0.4s；启动后前几秒打开面板会与启动回填争用磁盘，可能偶发一次 3–4s，非扫描本身（无固定延时）。已导入会话的「有新增」判定用文件大小 + 首行哈希，与导入账本比对：只有 mtime 变化（Claude Code 会原地重写 custom-title/last-prompt 等元数据记录）而大小与首行未变时仍视为已导入，不误报可重新导入；分段会话另需 `sourcePaths` 列表一致。
- 工作区分组键做 Windows 规范化（盘符大小写、斜杠方向、尾斜杠），`E:\a\b` 与 `e:/a/b` 合并为一行；底栏「Y 个工作区」计数同规则。分组来源是每条转录里记录的 cwd，已从 Qoder 侧栏移除但转录仍在的历史工作区也会出现，属预期行为。工作区名称取 cwd 的目录名；Qoder 侧栏的显示名（如 `20260929党会`、`food-order`）是 Qoder 自己的工作区别名，转录与本地配置中都没有，悬停行可看完整路径。cwd 为父目录本身（如 `E:\workproject`）的会话也会成组，Qoder 不一定把它列为工作区。Claude Code 的 rewind 分支按首条用户消息 UUID 归并：同一逻辑会话只显示活跃分支一行，行仍绑定首次导入的分支 ID；活跃分支路径变化时显示“有新增”，导入确认会提示按最新分支重建 DSH 会话。
- 应用行：单行；三态全选框统一在行首（扫描中用同尺寸占位保持列位），名称 14px/500（过长省略），会话/工作区计数移入名称 tooltip；行尾在展开箭头前显示批量撤回图标（该应用没有已导入/有新增会话时不显示；右侧几何与工作区行一致：18px 槽位 + 8px 间距 + 24px 箭头，图标与箭头纵向对齐）；一次撤回该应用全部已导入/有新增会话，确认弹窗显示数量并说明空工作区清理；整行可点击展开/收起（复选框保留独立行为），行尾箭头仅作指示（不可单独点击、无悬停提示）；搜索时全选作用于匹配会话。
- 工作区行：`folder + 名称 + N 个会话 + 单一聚合状态图标`；图标语义：已全部导入=对勾圆、部分已导入=按已导入比例填充的进度圆环（如 2/3 填 240°）、有新增=实心圆点（新内容提示，可重新导入）、失败=感叹号圆，完整文案（含数量或比例，如「部分已导入 2/3」）放 tooltip，行内不显示状态文字，也不显示「已选 N」。全选框在行首；行内不再显示会话计数（计数保留在应用行汇总与名称 tooltip）。状态图标与撤回共用一个 18px 槽位，右对齐固定在展开箭头之前，所有工作区图标纵向对齐；静止显示状态图标，悬停本行或槽位内键盘聚焦时状态淡出、撤回原位淡入（绝对定位 inset，无占位空洞、无位移；触屏两者并排常显）。工作区名称最长 320px，超出省略。行尾只保留计数与展开箭头（箭头纯指示）。整行可点击展开/收起（复选框与撤回槽位保留独立行为）。交换触发严格限定本行：工作区头行与会话行各自 hover，悬停子会话不联动父工作区行。工作区撤回一次撤回该工作区全部已导入 / 有新增会话，确认弹窗显示数量，失败项保留可重试。
- 会话行：行首复选框（与上两级行首选择列同模型）+ 标题 + 状态/撤回共用槽位（16px，位于标题之后；静止显示已导入 / 有新增 / 失败图标 tooltip，悬停或键盘聚焦时原位换为撤回；未导入不占位）。撤回最后一个会话时，宿主通过原生 `workspaceRegistry.delete(id)` 注销空工作区注册；磁盘目录、源会话与 DSH 会话日志都不删除。
- 底部吸底栏：左侧「已选 X 个会话 · Y 个工作区」（运行中或完成后显示状态），右侧「清除选择 / 导出日志 / 导入」；工作区按 cwd 去重计数。导入进度只显示「正在导入 当前/总数」，不显示会话 id。完成摘要带来源：单条显示「工作区 · 会话标题」，多条显示工作区名（不超过 2 个直接并列，否则「前两个 等 N 个工作区」；无工作区时显示首个标题 + 等 N 个会话）；摘要最多两行，超出才省略（`-webkit-line-clamp: 2`），按钮随行高垂直居中；悬停看全文。最近一次完成的任务在宿主进程内保留，重开面板会恢复该摘要与「导出日志」。宿主设置滚动容器有 24px 底部 padding，`sticky bottom:0` 停在其上方，padding 带会露出后面的列表行；吸底栏用同色 `box-shadow: 0 48px 0 24px` 连续盖住该带与左右 padding（offset 须 ≤ 栏高保证覆盖连续，spread 填左右）。不要用绝对定位伪元素，后者会增加可滚动高度，导致滚到底时操作栏被顶上去。
- 导入前弹窗确认；导入结束后导出 JSON 报告（run 汇总 + 每个会话的来源、状态、错误消息、轮次/事件数、耗时）；页面只显示汇总数字，报告不含会话正文。
- 导入性能：批量任务在宿主内 3 路并发（工作区挂载串行以保护注册表）；单会话热态约 0.3s（解析 ~10ms、写入+回读 ~90ms、投影预热 ~55ms、挂载 ~160ms），9MB 级会话约 1.9s；6 个会话实测总墙钟 2.1s。用户消息图片并行解析，避免多图串行等待。
- 导入任务在宿主侧执行：`POST /api/import-batch` 启动队列、`GET /api/import-status` 轮询进度。关闭设置页只会停止轮询，宿主继续导入；重开面板会接上正在跑的任务，最近 10 分钟内完成的汇总也会恢复（便于导出）。已有任务运行时再次启动返回 409（面板接管），导入期间撤回返回 409。
- 撤回与主视图：批量撤回包含当前打开的会话时，先切到本次不受影响的存活会话，再发撤回请求；宿主的设置弹窗在主视图回到空态（新会话页）时会自动关闭，若等会话行被移除后再跳转，弹窗会被动关闭。找不到可切换的存活会话时，视图清理延后到设置弹窗关闭后执行。

**样式基准**：不硬编码任何颜色，全部使用 DSH 设计令牌（`--dsw-alias-bg-*` / `-border-*` / `-label-*` / `-button-primary-*` / `--dsw-radius-*` / `--dsw-font-family`），字体 `14px/22px`、标题 `20px/28px`、按钮高 36、卡片圆角 `--dsw-radius-md`、焦点态 `2px var(--dsw-alias-state-business-primary)`，与 `dsh-connectors` 完全一致。

### 幂等状态（`src/host/state.ts`）

```ts
interface ImportRecord {
  providerId: string
  sourceSessionId: string
  sourcePath: string
  lineageId?: string
  fingerprint: { bytes: number; mtimeMs: number; headHash: string }
  dshSessionId: string
  importedTurns: number
  importedEventCount: number
  prefixHash: string
  boundaryHash?: string
  importedAt: number
  lastImportAt: number
  status: 'ok' | 'partial' | 'failed'
}
```

**处理流程**：`append` 只在目标会话空闲时执行（先 `prepare` 探测占用），占用则返回 `busy` 并提示稍后同步，避免破坏 seq 连续性。

### 自检脚本（`scripts/check-import.mjs`）

**业务说明**：用 DSH 自己的加载器当裁判，而不是自写断言。

**流程**：读取 `fixtures/` 下脱敏样例 → 走完整解析映射 → 写入临时 DSH 会话目录 → 调 `inspect()` 与 `deriveMessages()` → 比对期望的消息序列快照。任一环节失败即 `npm run check` 失败。

## 调用流程

```
用户点击「会话导入」
  → 面板 GET /providers          展示可用工具
  → POST /scan                   按 provider 扫描，返回元数据与估算 token
  → 用户勾选 + 选档位
  → POST /import                 服务端重读盘 → 解析 → 映射 → create → append
  → 事件流回报进度
  → inspect 自检
  → 面板显示三态结果（已导入 / 需检查 / 已跳过）并可一键打开或撤回
```

## 异常处理

| 异常 | 触发条件 | 处理 |
|---|---|---|
| `provider-unavailable` | provider schema 校验失败或根目录不存在 | 面板置灰并提示原因，不阻断其他 provider |
| `source-unreadable` | 路径不可读或越出白名单根 | 拒绝导入，记录一条告警 |
| `session-corrupt` | 坏行比例超过阈值（默认 30%） | 中止该会话，报告坏行数 |
| `append-busy` | 目标会话正被占用 | 返回 `busy`，提示稍后同步增量 |
| `inspect-failed` | 回读校验未通过 | 标记 `failed`，保留已有事件并给出首个异常事件位置 |
| `already-imported` | 指纹未变 | 返回 `skipped`，不重复写入 |

## 数据模型

新增的持久化数据只有一张映射表（`ctx.storage`），结构见上文 `ImportRecord`；DSH 侧不新增表结构，导入结果就是标准的 `session.v4.jsonl.zstd`。

## 风险与待验证

1. **首次续聊的压缩行为**：导入窗口若仍超出模型上下文，DSH 的自动压缩需要一个平衡区间一个区间地压。M0 必须实测一次，确认是否需要导入后再调用一次 `ctx.compaction.compactNow()`。
2. **附件写入接口**：attachment store 的写入方式需在 M0 期间确认；未确认前图片按占位文本降级。
3. **增量 append 的前置条件**：`prepare()` 能否安全用作占用探测，需实测。
4. **WorkBuddy 数据目录**：待定位，M4 前补齐。
5. **格式稳定性**：第三方格式无官方承诺，解析器需对未识别类型静默降级而非报错，靠 fixtures 回归。
